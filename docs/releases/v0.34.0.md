# v0.34.0

Runner v0.34.0 runs releases of dialect formats `4.0.0` and `4.1.0` on the run path (#299),
reads a paged source in a loop of pages and keeps a job's cursor between runs (#247, #300,
#302), and holds a caller with a verified identity to the scope identifiers its token and the
configuration both allow (#304, #305). `verify-preparation` reads dialect format `4.1.0`
(#292). CI runs the unit tests in shards and checks the merge queue's group (#269, #296, #297,
#298, #301).

A Runner started as before, with the sqlite kind, no `identity` and no job that names `paging`,
keeps its store's schema and answers as v0.33.0 did. **A Runner with `identity` checks caller
scopes by default** (see [What an operator must do](#what-an-operator-must-do)). The Spec's
maturity remains `draft`. This release claims no Extended Runner support.

A pre-release batch fixed the findings of the release review (#310):
`store migrate` refuses while a Runner holds an unexpired claim, the start says what checked
caller scopes change for an identity with no `callerScopes`, an occurrence's held pages are no
longer served, and the documentation now holds what the code does.

## Compatibility

| With | What holds |
|---|---|
| Earlier Runner state directories (sqlite kind) | Open with no migration. A store keeps its schema byte for byte until the first job that keeps a cursor (a job that names `paging`) is written, which raises it to schema `"8"`. Every earlier Runner refuses a store at schema `"8"`. |
| A PostgreSQL store migrated by v0.33.0 | Must be migrated with this release's `jpack-runner store migrate` before a v0.34.0 Runner starts on it: it applies `0007`, which raises the schema to `"8"`. v0.33.0 refuses the migrated store, so v0.33.0 and v0.34.0 Runners cannot share a store. One-way: there is no migration back; going back needs a backup taken before `0007`. |
| Service configuration files with `identity` and no `identity.callerScopes` | Caller scopes are checked: every subject is unscoped. The section below lists what changes. `"callerScopes": "unchecked"` keeps the behavior of v0.33.0. |
| Service configuration files with `identity.callerScopes` | Read by this release only: v0.33.0 refuses the member as one it does not read. |
| Releases of dialect formats up to `3.0.0` | Run as before; their release digest is unchanged. |
| Releases of dialect formats `4.0.0` and `4.1.0` | Run, with the release digest of RFC 0020 section 1 as staged for `specVersion` `0.6.0` (Spec vectors at `0d5bdea`): SHA-256 of the canon bytes of the whole retained release. The private offline workflow reader refuses a recording of either format `version-unread`, as the Spec's reader does until the format is accepted. |
| PostgreSQL | 16 is the version tested, as in v0.33.0. |
| Judgment Pack Runtime | The Runtime pins did not move; the Verified-with table lists them. |
| Judgment Pack Gateway | The durable Gateway contract the tests run against did not move (Gateway v0.28.0, `c5b12d2`). A paged read relies on the Gateway's `410 source_reference_expired` for an expired reference. The Runner's own Gateway calls carry no identity token and no scope identifier: a Gateway that holds its callers to scope identifiers (the Gateway's #479) needs a Runner change of its own, which this release does not build. |
| Desk | Not pinned by this release; Desk adopts it in its own lane. |

## Behaviour changes

- **Caller scopes are checked by default with `identity`** (#304, #305). An installation with
  `identity` and no `identity.callerScopes` has every subject unscoped:
  - a token whose claims carry `scope_ids` is refused `401` on every route;
  - every record under a scope identifier reads as absent, so an event delivery to a trigger
    under one gets the unknown-trigger answer, and a sender may drop it;
  - `POST /v1/ticks` answers `403 installation_caller_required` until a subject has an
    `"installation"` entry, so an external scheduler's shared ticks stop.

  The start says so on standard error: `caller scopes are checked (identity.callerScopes is
  absent): ...`.
- `POST /v1/jobs` under a scope identifier the caller does not reach answers `403
  scope_not_allowed`; a listing keeps only the scopes the caller reaches; `GET /v1/status`
  leaves out `triggersOutsideSettings` for every caller but the installation's (#305).
- An `occurrence.ready` journal entry that names a source in `fullReRead` or `cursorHeld` has
  `entryVersion` `"6"`. Clients that read the journal must accept `"6"` (#299, #302).
- An occurrence and a run of a paged job carry a `paging` member that says what was read.
  Clients must accept it (#299, #302).
- An occurrence's held pages (kept for a throttled attempt) stay on the record and are not
  served: the occurrence routes and the event-replay answer leave them out, and `openapi.json`
  no longer describes a `heldPages` member (#310).

## What an operator must do

- **Nothing, to keep running as before on the sqlite kind without `identity`.** Stop Desk and
  Runner and back up the Jobs workspace before the upgrade, as
  [State and backups](../../README.md#state-and-backups) describes.
- **With `identity`, write `identity.callerScopes` with this release's binary as it is
  installed:** an `"installation"` entry for the external scheduler's subject, and entries for
  the scoped callers and the event senders. Or set `"callerScopes": "unchecked"`, which keeps the
  behavior of v0.33.0 and which the start and `GET /v1/status` (`"callerScopes":"unchecked"`)
  say. v0.33.0 refuses the member: going back to it means removing the member.
- **To upgrade a PostgreSQL store:**
  1. Stop every Runner of the store.
  2. Run v0.34.0's `jpack-runner store migrate --connection <absolute path>` with the same
     logins as the first time. It applies `0007` and prints `{"applied":["0007"]}`.
  3. Start v0.34.0 Runners only.

  `store migrate` now refuses before applying a file while a Runner holds an unexpired claim on
  a run or an occurrence ("the store holds N unexpired claims", naming the runs and the
  occurrences): a Runner checks the migrations only at its start, so one still running after the
  migration would keep claiming work under the earlier schema. A claim's lease runs out 60 s
  after its last renewal. The store records nothing about a Runner beyond its claims, so a
  Runner that holds none is not seen: stop every Runner first all the same.
  `--even-with-live-claims`, after the connection file's path, applies the files regardless.
- **Know that the upgrade is one-way.** v0.33.0 refuses the migrated PostgreSQL store, and a
  sqlite store at schema `"8"`. Take the backup before migrating.
- **Paging is not offered over durable Gateway connections.** A job whose release's sources are
  acquired over a durable connection and that names `paging` is refused
  `paging_durable_unsupported`.
- **A paged job with overlap `"queue"`.** Its next occurrence waits, accepted, before it reads
  the job's cursor while the job has a run queued or running, or an earlier occurrence that is
  accepted, preparing, waiting or needs attention, so that two runs do not read the same window
  (#307, #312). An earlier occurrence left needing attention holds the later ones until it settles
  or their queue time ends. A completed run whose cursor advance no longer applies is recorded
  with that read `held: "moved"`, and its `run.completed` entry names the source in `cursorHeld`.
- **A retry of an interrupted paged run** is refused `409 run_not_retryable` while the job has
  other work in progress, or once another run has moved the cursor the run read (#312).

## New

- **Dialect formats `4.0.0` and `4.1.0` on the run path,** with capabilities
  `dialect-format-4.0.0` and `dialect-format-4.1.0` (#299). A workflow stage may name either
  format (#302).
- **Paged sources and a job's cursor** (`job-paging`, #247, #299, #300, #302). A job names
  `paging`, one rule per paged source: `kind` `"change"` or `"window"`, the `parameter` the
  cursor fills, and its `first` value. Each page is asked in one session and kept as its own
  receipt; the cursor advances only when the run made from the occurrence completes. A window
  read wider than `maxPages` keeps a position inside the window, and the next run continues
  from it. Refusals: `invalid_paging_rule`, `paging_source_unknown`, `paging_parameter_unknown`,
  `paging_durable_unsupported`; an occurrence whose window cursor starts after the instant it is
  prepared fails `paging_window_inverted` and leaves the cursor.
- **`GET /v1/jobs/{job}/cursors`** answers each paged source's cursor: its kind, its value, the
  run that last moved it and when, and whether its window is unfinished. It is served on both
  kinds, held to the caller's scope.
- **`identity.callerScopes`,** per listed subject an array of 1 to 256 scope identifiers it may
  be granted, `"unscoped"` or `"installation"`, or `"unchecked"` for the whole member; the token
  names its scope identifiers in the claim `scope_ids`, as the Gateway reads it (#305, ADR 0002,
  now accepted). Codes `scope_not_allowed` and `installation_caller_required`.
- **`store migrate --even-with-live-claims`** (#310).

## Fixed in the pre-release batch

- **`store migrate` did not check for running Runners.** It now refuses while a Runner holds an
  unexpired claim on the store, unless `--even-with-live-claims`; tested on PostgreSQL.
- **An upgrade with `identity` and no `callerScopes` changed more than the ticks.** The README
  lists all three changes, and the start says that caller scopes are checked and what follows.
- **The occurrence routes and the event-replay answer served an occurrence's held pages**, which
  hold the pages, the open session, the first page's request and the profile. They are now
  private, as a task's request and profile are.
- **Documentation:** entry version `"6"` is also set for `cursorHeld`; the paging design record's
  rule on pages never asked again names the exception of an expired reference; the README has a
  section on paging, cursors and schema `"8"`; ADR 0002 is accepted.
- **Checked, not reproduced:** a release whose `release.json` the format-4 pin accepts and the
  re-freeze refuses. A recording whose bytes differ from their typed encoding is refused
  `input-malformed` before either digest is compared, and a format-4 recording is refused
  `version-unread` before that.

## What this release does not establish

- **A change-reference read that stops at `maxPages` keeps no position (#303).** It moves nothing,
  so a change feed longer than `maxPages` per run does not advance; a window read does.
- **Previews from a caller held to scopes are journaled with no scope identifier (#306).**
- **The Runner as a scoped caller of the Gateway.** Its Gateway calls carry no identity token and
  no scope identifier.
- **A start that meets an unreadable trigger or job record is refused (#295),** as before.
- **Routes not served on the PostgreSQL kind** stay as listed in the
  [v0.33.0 notes](v0.33.0.md#what-this-release-does-not-establish).
- **No process group on stop (#265).**
- **Tests not built (#267).**
- **Removal of one scope's rows is not built** (#250). `jpack-runner store` takes `migrate` and
  nothing else.
- **Restoring a store from a backup is not tested.**
- **Replacing Runners one at a time is not supported (#257).** A store holds one release: stop
  every Runner to upgrade.
