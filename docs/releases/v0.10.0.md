Runner v0.10.0: the mapping v2 preparation vectors are published for a second reader, byte for byte, and the canonical form of a preparation is stated once.

## What an operator must do

- **Nothing.** Exports, the journal, `verify-run`'s report, its exit codes and refusal flags are byte-identical to v0.9.0's. No Runtime pin moves: CI keeps Runtime v0.31.0 and v0.27.1.
- **A reader of the contract** finds the canonical form of a preparation stated once, in `docs/MAPPING-V2.md` under "The canonical form of a preparation" (member order, numbers as written within ±(2^53−1) with no fraction or exponent, string escaping, nesting, `verifiedAt`'s form, what the digest covers), by reference to the vectors.

## The preparation vectors (#77, closes #75)

- **`vectors/preparation/`** holds nine vectors, hand-maintained normative data in the gateway corpus's manner: a README, a manifest naming each vector's files and the exact report `verify-run` gives for it, and one directory per vector with the mapping document, the retained source records, the input profiles by digest, the preparation's exact canonical bytes with `verifiedAt`, its digest, and what the verifier reads. The valid case (which also holds a calculated value) and `recomputed-one-second-later`, `foreign-binding-kind`, `changed-table-lineage` and `disposition-differs-from-audit`, each altering one thing with one finding; `unbound-record`, `unsigned-parameters` and `escaped-strings` from the existing fixture families; and `numeric-spellings`, which keeps `-0`, `9007199254740991` and `-9007199254740991` as written so a reader that normalises numbers fails it.
- **Generated once, not regenerated.** A program apart from the service (`tools/preparation-vectors/`) wrote them from the fixtures under Runtime v0.31.0; CI does not run it. Changing a vector is a contract change. `.gitattributes` marks the directory `-text`, so no checkout converts a line ending.
- **Two tests hold them.** `TestPreparationVectorsAreByteExact` recomputes every preparation through the Runner's own code and compares the bytes and the digest; `TestVerifyRunReportsEachPreparationVector` runs `verify-run` and compares its report byte for byte, finding names and order included. Neither needs a Runtime binary or the network.
- **Why.** The specification takes this format up as the dialect (judgment-pack-spec RFC 0018, a Draft, whose staged vectors are these, byte for byte), with a preparation-verifier reader class, so a third party can hold a runtime record's binding digest (runtime ADR-0050) to a preparation without the Runner's code. RFC 0000's evidence bar needs two independent readers agreeing on vectors; these are the vectors.
- **Test-only additions:** a fixture family `mapping-v2-calculated-bound` written once by an existing test through the `JPACK_V2_CALCULATED_EXPORT_DIR` hook, and `mapping-v2-calculated-numeric` likewise, both under Runtime v0.31.0, signed with the seed of RFC 8032's first test vector as the test helper signs.

## Verification

CI ran formatting, vet, the race tests and the real-Runtime integration tests on Linux and macOS at the pull request's head and again at the tag, with Runtime v0.31.0 and v0.27.1 built at their release commits, and the release-contents check.

- **Mutation checks:** eleven, each caught by a named test: a byte of a vector's preparation flipped, the same flip with the digests updated to match, the generator writing members unsorted, the valid case regenerated one second later, one verifier rule dropped for each of the five altered cases, and the generator normalising `-0` or writing an integer with an exponent.
- **Review:** one cross-vendor round (OpenAI model, medium effort, read-only) at 822a84a, recorded on the pull request with the maintainer's disposition: no HIGH or MEDIUM; one LOW, the numeric spellings uncovered, fixed in the same pull request as the ninth vector. The reviewer recomputed every preparation through the Runner's code and matched `verify-run`'s report for every case.
