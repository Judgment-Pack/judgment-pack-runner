Runner v0.16.0: every acquisition receipt is held to the dialect companion's §5.2 by one rule, for operations, selected files and research alike; a receipt's `sessionId` is any string, and the pinned Runtime reads it so through evaluation; the first skipped-source vector is recorded; a host recovers a completed job upgrade's receipt without a new write.

## What an operator must do

- **Nothing for existing runs.** Exports, the journal, `verify-run`'s report, its exit codes and refusal flags are byte-identical to v0.15.0's for every existing run; all thirty-eight published vectors recompute byte for byte, and the thirty-ninth beside them. A receipt the gateway wrote is unchanged in what it carries: the gateway stamps whole seconds and flat session tokens, so no live receipt is refused by the tightened rule.
- **If another producer writes receipts**, know that both instants must now be whole seconds in UTC, each between the source's `maxAge` before the preparation's instant and 30 seconds after it, the adapter must equal the profile's as a whole object, and `sessionId` may be any string; a run that cites such a receipt needs the Runtime this release's CI pins (`09206e7`) or later, which reads any citation session.
- **To recover a lost upgrade acknowledgement**, read the receipt endpoint with the upgrade's request identity; it performs no write and no readiness check.

## One receipt rule under §5.2 (#103, closing #98; #104, closing #99)

- Operation and selected Drive file receipts follow §5.2 as research receipts do: `servedAt` and `observedAt` each inside the window, edges included, with no rule tying one instant to the other; both instants held to the whole-second UTC form before the time rule; the adapter compared with the profile's as a whole object; one function serves every receipt, and every caller goes through it. An unparseable serving time is "invalid serving time", no longer "stale".
- A receipt's `sessionId` is read as any JSON string, the empty string included, and refused only when it is not a string; the session rule compares exact strings; the citation carries the string as given. The CI pin moves to the Runtime that reads such a citation at evaluation (judgment-pack-runtime#291), and an end-to-end test runs an arbitrary and an empty session through evaluation, export and `verify-run`.

## The skipped-source vector (#105, for judgment-pack-spec#189)

- `skipped-source-dependency-unavailable`: three operations through one profile, the third skipped because a source it waits on gives its parameter no value. It holds the form the Runner writes and the specification now states (RFC 0018 round 12): the outcome's claim present with reason `dependency-unavailable` and status `unknown`, each lineage entry's status `unknown` and its `dependencies` as objects in parameter order; the thirty-eight earlier vectors were written again byte for byte by the same generator run.

## Job upgrade receipts recovered read-only (#102)

- An authenticated read-only endpoint returns the exact completed revision's receipt by the upgrade's request identity, before commit, after later revisions and after a restart; malformed and duplicate queries are refused; no write and no readiness check is performed.
