Runner v0.13.0: the release workflow publishes by id after comparing the draft's assets by the digests the releases API reports and re-reads them after publication; the version-3 encoding rule runs on the event route too.

## What an operator must do

- **Nothing.** Exports, the journal, `verify-run`'s report, its exit codes and refusal flags are byte-identical to v0.12.0's for every existing run; the twelve published vectors recompute byte for byte.
- **One observable change on one route:** `POST /v1/triggers/{trigger}/events` now refuses a version-3 document written under a member that is `mapping` but for case, or beside the exact member, as `invalid_source_input` with the same message as the other routes, before the event's mapping is compared with the release's. An event written as the Runner keeps it is unchanged.

## The release workflow (#89, closes #87)

- The draft-creating job records the draft's release id, reading the releases listing again until the draft appears. The publish job reads the release by that id through the API with no download (draft state, tag, title, prerelease flag, notes, and each asset's `digest`), compares it with the run's own files, refuses on any difference with both digest sets printed, publishes by id, and re-reads the published assets' digests. Two failures are told apart by name: "does not hold what this run packaged", with both digest sets, and "could not be verified", with the API error and no diagnosis.
- `docs/releasing.md` states the residual window between the last read and the publish call, who can act in it, and what a maintainer does on each failure. This release is the first run under the new step.

## The event route (#90, closes #84)

- The event handler decodes its body through the same rule as the preview, next and run routes; the event's existing check that its mapping hash-equals the release's frozen mapping runs after it, unchanged. `docs/MAPPING-V2.md` and `openapi.json` name the event delivery in the encoding rule's sentence.

## Verification

CI ran formatting, vet, the race tests and the real-Runtime integration tests on Linux and macOS at each pull request's head and again at the tag.

- **Mutation checks:** the event route reverted to the plain decoder fails the new test for the encoding reason; the publish job's shell steps were simulated against a stand-in in four cases (a matching draft published; an asset changed before the last read refused; a swap in the window published and then failed by name with both digest sets; an API error after publication failed as "could not be verified").
- **Review:** one cross-vendor round each (OpenAI model, medium effort, clean room), recorded on the pull requests: #89 one MEDIUM (the recovery guidance read a read failure as tampering) fixed with the named distinction; #90 one LOW (a control assertion) fixed.
