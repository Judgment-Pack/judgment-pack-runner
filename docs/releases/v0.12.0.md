Runner v0.12.0: a dialect version-3 document is read; an unbound source is bound at import, through a binding document the operator supplies, to this installation's input profiles; each version-3 kind is prepared or refused by name; two vectors hold it.

## What an operator must do

- **Nothing for existing runs.** Exports, the journal, `verify-run`'s report, its exit codes and refusal flags are byte-identical to v0.11.0's for every existing run; the ten published vectors recompute byte for byte.
- **One observable change for version 2:** a version-2 source that names a version-3 member is refused by name as `invalid_source_input` (422); before, it was refused as an unknown member (`invalid_request`, 400). Nothing that was accepted before is refused now.
- **An operator holding a published dialect** (RFC 0018 version 3, unbound) may now import it: the request names the published document and a binding document under `source.import`, and Runner makes the bound dialect for this installation's profiles.

## Dialect version 3 (#83, closes #82)

- A version-3 document whose sources are all bound prepares as the version-2 document with the same sources does: the preparation's bytes are the same but for `version` (3) and `mappingDigest` (the digest of the document's canonical form). Version 3 carries no `provider`, `facts` or `evidence`.
- **Kept as written.** A version-3 document is read only at `source.mapping` (`input.source.mapping` in a preview), each member named exactly so: a document under a member that is one of those names but for case, or beside such a member, is refused as `invalid_source_input`; one Runner would write otherwise (an optional member written empty) is refused by name, not kept under another digest.
- **The import step.** `source.import` carries the published `dialect` and a `binding` (the published digest and, per unbound source, a profile id and digest). Each unbound source's `platform`, `operation`, `shape` and `record` are replaced from the profile; every other member stays as written; the bound dialect becomes `source.mapping`. Refused, each with a sentence that names it: a dialect not of version 3, with no unbound source, or written otherwise; a binding for another digest, with members beyond `dialect` and `sources`, or an entry member beyond `profile` and `profileDigest`; a source left unbound, a name that is not a source, or a source already bound; a profile this installation does not hold by that id and digest, or whose shape or adapter is not the source's.
- **A mapping given beside an import** (`{}` and `null` included) must be the bound dialect byte for byte in canonical form, or the request is refused; Runner makes the mapping only when the member is absent.
- Both documents are kept as given beside the run in `source.import`, as the operator's record. No preparation holds their digests or any catalog name; every later preparation binds them again under the profiles it is given.
- **The kinds:** `operation` is prepared as version 2's, under every adapter shape, bound or bound at import; `selected-file` through the existing selected-snapshot path (`local-file` asserted, `google-drive` verified under its `drive` profile); `http`, `sql` and `web` are refused by name; `research` is refused by name, naming Judgment-Pack/judgment-pack-spec#161.
- `vectors/preparation/version-3-bound` (the valid case's mapping written as version 3) and `vectors/preparation/unbound-bound-at-import` (`unbound.json`, `binding.json`, `mapping.json` as Runner made it, and the preparation; the manifest entry's `import` member says which file is which): two vectors, signed, witnessed and bound, generated by `tools/preparation-vectors` under the published Runtime 0.31.0. The ten earlier vectors were written again byte for byte by the same run.
- `docs/MAPPING-V2.md` defines version 3's reading, the import step and both refusals; `openapi.json` gains `InputMappingV3`, `source.import` and the version-3 refusal codes.
