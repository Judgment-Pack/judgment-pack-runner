The first release of this repository. One candidate came before it, `v0.1.0-rc.1`. Runner remains a **research preview**: a single-owner, local Jobs pilot.

## What an operator must do

Nothing changes in what Runner does: the programs are built from the code of `v0.1.0-rc.1`. Since the candidate, CI tests that code with released versions of Runtime and Gateway, and the README names a fault that was there.

**Read the known fault below before scheduling a mapping that has more than one operation source.**

## Known fault: an unattended run with two or more operation sources is refused (#5)

An unattended run of a mapping with two or more operation sources never completes. Runner acquires each source in a Gateway session of its own, and its own verifier then refuses the set, since it takes acquisitions of one session only. The run is refused and no decision is requested on input that was not verified.

Not affected: a mapping with one operation source; preparation in Desk, which uses one session for all sources; local-file sources.

It is not fixed in this release. Which of the two rules gives way is a decision that has not been made.

## What a release carries

Four archives, for Linux and macOS on `amd64` and `arm64`. Each holds `jpack-runner`, `jpack-source-worker`, `jpack-google-relay`, `openapi.json` and the licences. Windows is not released: it compiles, and nothing tests it.

To verify a download:

```sh
sha256sum --check --ignore-missing checksums.txt
gh attestation verify <archive> \
  --repo Judgment-Pack/judgment-pack-runner \
  --signer-workflow Judgment-Pack/judgment-pack-runner/.github/workflows/release.yml \
  --source-ref refs/tags/v0.1.0
```

`jpack-runner version` and `jpack-source-worker version` print the release a program was built for.

"Release" here is a release of this repository. A frozen pack release, which Runner records when a job is created, is a different thing and is unchanged.

## What Runner does at this release

Runner turns a reviewed pack snapshot into a durable job. It checks a release, takes facts and evidence availability, runs the pinned evaluator, and keeps the result and its audit history on the local filesystem, with SQLite holding the queue and records.

- Durable local schedules, stable JSON file changes, authenticated events and Google Cloud Scheduler delivery.
- Verified mapping v2, and unattended Gateway operation mappings, with the fault named above.
- Durable source preparation that resumes after a restart, and source responses retained by a separate caller worker.
- The companion protocol is `jobs/1`. Its HTTP contract is `openapi.json`.

Not implemented: AWS and Azure adapters, external actions, graph execution, shared-user permissions and AI agent loops.

## What this release does not establish

- The `darwin/amd64` archive is built and read, and run by nothing. `jpack-google-relay` is started by no release check.
- The release checks start no job. That needs Runtime and a boot line from Desk, which CI covers from source.
- No test reaches the known fault: none runs an unattended mapping with two operation sources to its end.

[docs/releasing.md](https://github.com/Judgment-Pack/judgment-pack-runner/blob/v0.1.0/docs/releasing.md) says how a release is made and what each check does not establish.
