# v0.28.0

Runner v0.28.0 carries four changes since v0.27.0:

- shared mapping-v2 preparation fixes found by the workflow admission experiment (#200, #201);
- workspace and input roots that are strictly UTF-8 (#202, #203);
- tests and a design section showing that selected preparation runs beside a full ordinary
  profile registry (#190, #205);
- the pre-release batch, which covers runs queued across the upgrade, exact refusal bytes and
  an unreadable input root (#207).

The first two change what the Runner accepts. Some hosts, dialects, queued runs, exports and
stores that worked with v0.27.0 are refused by v0.28.0, as set out below. The companion pins
do not move. The Spec's maturity remains `draft`. This release claims no Extended Runner
support.

## Breaking changes

1. **The `adapter-http` query is held to dialect §4.1 (#201, #207).** Under a profile whose
   `adapter.name` is `adapter-http`, a request whose `query` breaks the rule is refused
   `profile-mismatch` before acquisition.
   - **Refused forms:**
     - a query that is a string, `null`, an array, a number or a boolean;
     - a whole-value `$param` or `$text`;
     - any member other than a string, a `$text`, or a `$param` of a `string` or `timestamp`
       parameter. So no integer, boolean, `null`, object or array literal is accepted, and no
       integer-typed `$param`.
   - **Where it shows:**
     - HTTP 400 `invalid_source_input` on `/v1/inputs/next`, `/v1/inputs/preview`,
       `/v1/previews`, run submission (`/v1/jobs/{job}/runs`),
       `/v1/retained-column/1/selected-inputs/next`, trigger preview
       (`/v1/jobs/{job}/triggers/preview`), trigger creation (`/v1/jobs/{job}/triggers`)
       and deliveries (`/v1/triggers/{trigger}/deliveries`);
     - queued runs and accepted occurrences fail at dispatch;
     - durable preparations go `needs-attention`;
     - `verify-run` refuses;
     - `verify-preparation` reports `profile-mismatch`.
   - **Saved releases:** a release saved with such a query can still become a job, and every
     run of that job then fails. Preview such a release again before you create or upgrade a
     job from it. A check at job creation and upgrade is a follow-up for v0.29.0.
2. **A dialect preparation with no evidence target now derives and retains evidence `{}`
   (#201).**
   - The preview and plan `evidenceText` is `"{}"`.
   - `run.input.evidence` is `{}`.
   - The audit record's evidence is `{}`, with `evidenceSupplied: true`.
   - The Runtime is now given `--evidence`, so decisions can differ from those v0.27.0 made.
3. **`verify-run` refuses an export whose retained facts or evidence differ from the
   derivation, including when they are omitted (#201, #207).**
   - This covers every dialect run with no evidence target made by v0.27.0 or earlier. There
     is no repair: verify earlier runs with the Runner that made them.
   - An export in the shape an earlier Runner made has its own sentence:
     `the export is in the shape a Runner before 0.28.0 made: its run retained no
     evidence-availability document where the derivation is {}, and this Runner does not
     verify such an export`. Any other difference gives `retained facts or evidence do not
     match verified derivation`.
   - A run queued on v0.27.0 and dispatched on v0.28.0 is refused before the Runtime runs. It
     ends `failed` with the new reason `prepared-by-earlier-runner`. **Drain queued runs
     before upgrading.**
4. **The boot line is refused before any state is created (#203).**
   - Any non-UTF-8 byte in any member gives `request-not-utf8`.
   - An unpaired surrogate escape in `dir`, `workspace`, `runtime` or `inputRoot` gives
     `path-unpaired-surrogate`. This covers any case spelling of the member, escaped member
     names, and every occurrence.
   - NUL gives `path-contains-nul`.
5. **Go hosts (#203).** `runner.Open` and `runner.RelocateWorkspace` refuse with
   `path-not-utf8` and `path-contains-nul`. That includes Latin-1 raw-byte paths, which
   opened before.
6. **A store whose stored input root binding is not UTF-8 or holds NUL is refused (#203).**
   The store is refused at open and at relocation, with `stored-binding-not-utf8` or
   `stored-binding-contains-nul`. Re-create the workspace.
7. **Relocation refusals (#203)** change from "invalid relocation request" to the coded
   messages below.

## Additive changes

- `GET /v1/status` gains `inputRootReplacementCharacter` and `inputRootExists` (#203), and
  `inputRootUnreadable` for a root that could not be read (#207).
- `serve` writes a note to standard error at open when the input root binding holds U+FFFD.
- The `openapi.json` `Status` schema names these members.
- `Run.reason` gains the value `prepared-by-earlier-runner` (#207).
- The workflow-freeze changes are test-only. The workflow writer is private, and no route
  reaches it.

## What an operator must do

- **Drain queued runs before upgrading.** A run queued on v0.27.0 and dispatched on v0.28.0
  may fail with `prepared-by-earlier-runner`. To recover, submit its input again.
- **Fix `adapter-http` queries.** Re-preview each such dialect with an object `query` of
  string templates, such as `{"query":{"q":{"$param":"query"}}}`, and release again.
  Preview a saved release again before you create or upgrade a job from it.
- **Keep the earlier Runner for earlier exports.** v0.28.0 does not verify exports of dialect
  runs with no evidence target made by v0.27.0 or earlier.
- **Refuse non-UTF-8 roots in the host.** Raw-byte roots are not supported, and there is no
  byte-exact relocation route. A host whose source root is not valid UTF-8 must refuse it
  before it creates a workspace or queues a relocation.
- **Re-create a workspace whose stored binding is outside the rule.** No operation rewrites
  such a binding.
- **Check a binding that holds U+FFFD.** It still opens, and it is flagged as described
  below. If its root does not exist, the binding may have been made from a path that lost
  bytes.
- The usual care applies before any upgrade: stop Desk and Runner and back up the Jobs
  workspace, including SQLite/WAL, as
  [State and backups](../../README.md#state-and-backups) describes. The store schema is
  unchanged and there is no migration.

## Shared preparation fixes (#200, #201, #207)

The workflow admission experiment (#146, which does not merge) found these fixes. They are
carried here without its workflow code.

### The derived evidence document always reaches the Runtime

A version-2 or version-3 dialect preparation now always passes both derived documents to
the Runtime, including an empty evidence-availability document, `{}`
(spec/dialect.md §8.1). Before this release, a preparation with no evidence target was
evaluated without `--evidence`, and its audit record kept
`"evidence":null,"evidenceSupplied":false`. A version-1 file mapping is not a dialect
preparation and keeps its optional evidence.

For such dialects, API clients see:

- `/v1/inputs/preview` and `/v1/jobs/{job}/triggers/preview` return `evidenceText: "{}"`
  where they returned `""`.
- `/v1/inputs/next` returns `evidenceText: "{}"` where it left the member out.
- `/v1/previews` has no `evidenceText`; its `sample.evidence` is now `{}` where it was absent.

### `adapter-http` query templates are held to the dialect

The parameters in scope for a query template are the case's and the source's own. Other
`http`-shaped adapters are not held to this rule. The refusal code is the existing
`profile-mismatch`. The messages, each prefixed by `source <name>: `, are:

- `adapter-http query must be an object of string templates`
- `adapter-http query must not be a template form`
- `adapter-http query member "<name>" must be a string template`. The member name is quoted,
  so a newline in it cannot start a new line (#207).

The same check, `profileRequestForm`, runs at preview, before acquisition, at every
preparation and in `verify-run`. `openapi.json` (`MappingSource.arguments`) and
[MAPPING-V2](../MAPPING-V2.md) state the rule.

### Retained inputs are held to the derivation

`verify-run` compares a run's retained `facts` and `evidence` with the verified derivation,
as JSON values. Exports whose retained members are only reordered still verify. Every export
checked in to this repository derives at least one evidence target and still verifies.

Dispatch now holds a queued run's retained inputs to its recomputed preparation in the same
way, before the Runtime is invoked (#207). A run in the v0.27.0 shape has the derived facts
and no `evidence` member, where the derivation is `{}`. Such a run is refused, not repaired.
It is never evaluated without evidence, and `{}` is never filled in. It ends `failed` with
reason `prepared-by-earlier-runner` and this problem:

> This run was prepared by a Runner before 0.28.0, which left out its empty
> evidence-availability document. This Runner evaluates a dialect run only with the evidence
> its preparation derives, {} here, so the run was not evaluated. Submit its input again:
> this Runner's preparation derives the document.

Any other difference fails the run with `retained facts or evidence do not match verified
derivation`, and no reason.

## Workspace and input roots are strictly UTF-8 (#202, #203, #207)

Runner now refuses a path it cannot represent exactly. The rule covers:

- the boot line's `dir`, `workspace`, `runtime` and `inputRoot`;
- the same members of a direct Go host's `runner.Config` (`runner.Open`);
- a relocation's `dir`, `workspace`, `previousInputRoot` and `inputRoot`, through
  `relocate-workspace` and `runner.RelocateWorkspace`;
- the stored input root binding.

Each must be valid UTF-8 with no NUL. Before this release:

- the boot line was decoded with `encoding/json`, which turned an invalid byte or an unpaired
  surrogate escape into U+FFFD, a different path;
- a NUL from a decoded <code>&#92;u0000</code> was accepted;
- a direct Go host could pass raw bytes or NUL.

Each refusal ends with its code in parentheses, and none creates or records anything:

- `request-not-utf8`: the boot line or relocation request is not valid UTF-8. This is
  checked before decoding.
- `path-unpaired-surrogate`: a path member has a `\u` surrogate escape with no matching pair.
- `path-not-utf8` and `path-contains-nul`: a path is not valid UTF-8, or contains NUL
  (including a decoded <code>&#92;u0000</code>). These name the member, not its value.
- `stored-binding-not-utf8` and `stored-binding-contains-nul`: the store's input root
  binding is outside the rule. The refusal shows the binding with its bytes escaped, and
  Runner does not guess the original.

**A binding that holds U+FFFD.** A binding that is valid UTF-8 with no U+FFFD opens and
relocates as before. A binding that holds U+FFFD also opens. Runner cannot tell a literal
U+FFFD from one that replaced a lost byte, so it flags the binding:

- Whenever an input root is bound, `GET /v1/status` reports `inputRootReplacementCharacter`.
  - It also reports `inputRootExists`, which says whether the bound root exists as a
    directory.
  - When the root's status could not be read, for example because access was denied,
    `inputRootUnreadable: true` replaces `inputRootExists` (#207).
  - None of these members appears without an input root.
- At open, `serve` writes one line to standard error when the binding holds U+FFFD. The line
  says the bound root exists, does not exist, or could not be read.
- A Go host reads the same from the new `Service.InputRootBinding()`.

Exact source and destination identity, the prior-binding comparison, operation-ID replay,
and retained run, release and audit bytes are unchanged. A literal U+FFFD in a valid path
still round-trips byte for byte. The README section
[Paths are UTF-8](../../README.md#paths-are-utf-8) states the rule.

## Selected preparation beside a full ordinary registry (#190, #205)

This release changes no runtime code for #190. The selected-profile namespace from v0.27.0
(#191, contract `selected-profile-preparation/1`) already meets its need. Two new tests run
that host:

- one has 15 configured profiles plus the installed ordinary generated-input profile, with an
  ordinary run held in the executor;
- the other has ordinary profiles that together exceed `profilesBytes`.

They pin each boundary refusal byte for byte. A new section of
[selected-profile preparation](../design/selected-profile-preparation.md), "A full ordinary
registry", gives the answer. #190 stays open until Desk accepts it.

## Known limitations

- **Hung mount.** Every `GET /v1/status` stats the bound input root, so a mount that does not
  answer can hold the status reply. A fix is planned for v0.29.0.
- **Path members not checked.** The boot line's `signingKey` and `executorOwnership.root` are
  not held to the path domain. The whole boot line must still be valid UTF-8.
- Raw-byte workspace and input roots are not supported, and there is no byte-exact
  relocation route (#202).
