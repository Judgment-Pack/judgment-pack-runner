One addition: an installation can declare a calculator, and a value it computed reaches a pack saying so, held to the case it was computed for. A store, a boot line, a profile and a mapping that `v0.2.0` accepted are accepted the same, and encode the same; nothing new happens unless it is declared.

## What an operator must do

- **Nothing, to keep things as they are.** Profiles, mappings, runs and exports without a calculator are unchanged, byte for byte. Their digests do not change, and an export written by `v0.2.0` verifies under this release; a test holds one such export to that.
- **To declare a calculator:**
  - give its trusted profile `calculator: {name, version}`; the profile must be `record` and `mcp`;
  - give each source that uses it `calculation: {inputs, tables}`.
  - [MAPPING-V2.md](https://github.com/Judgment-Pack/judgment-pack-runner/blob/v0.3.0/docs/MAPPING-V2.md#calculated-values) has the contract.
- **Desk does not write calculators yet.** Desk `v0.3.0` runs Runner `v0.2.0`. A Desk that moves to this release offers a calculator profile, but writes the source without `calculation`, and preview refuses that until Desk adds the binding. Until then, write the binding in the mapping's JSON.

## A calculated value says what it is (#22, closes #14)

A value a formula produced already reached a pack as a record fact. Nothing said it was calculated, by which calculator, from what inputs, from tables how old, or why there was no value when the calculator could not compute one. [The design record](https://github.com/Judgment-Pack/judgment-pack-runner/blob/v0.3.0/docs/design/calculated-values.md) decides the five questions of #14:

- **The installation declares it.** A trusted profile carries `calculator: {name, version}`. By declaring it the installation asserts that each allowed tool computes a deterministic function of the inputs it echoes and the tables it reports, and calls no model. Runner cannot check that. A calculator that calls a model is a `generated` profile and cannot be declared a calculator.
- **The answer says what it is.** After `unwrap`, the answer carries a `calculation` member of exactly four members:
  - `calculator`: the pinned name and version;
  - `status`: `computed`, `input-missing` or `cannot-compute`;
  - `inputs`: each input used, by name;
  - `asOf`: an instant for each table read.
- **The mapping binds it, and preview checks the pairing.** A source declares `calculation: {inputs: {name: parameter}, tables: {name: maxAgeSeconds}}`. A calculator profile without it, or it without a calculator profile, is refused before any acquisition.
- **Preparation holds the answer to the case.** It fails unless the answer names the pinned calculator and version, every echoed input is bound and equals its parameter as canonical JSON, and every reported table is named. A `computed` answer must also echo every bound input and report every named table, no older than its limit and no more than 30 seconds ahead.
- **A failed calculation is `unknown`, under its own reason.** For `input-missing` or `cannot-compute`, Runner does not apply the source's read:
  - there are no facts, and each mapped evidence requirement is `unknown`;
  - the reason is `calculation-input-missing` or `calculation-cannot-compute`;
  - dependent sources record `dependency-unavailable`.
- **The lineage records it.** Each entry of an acquired calculated source carries `calculation`: the calculator, the status, each echoed input with where its value came from, and the tables' instants. `verify-run` recomputes it.

## What this release does not establish

- That a calculator is deterministic, calls no model, or computes correctly; that it used only the inputs it echoes; or that its `asOf` instants are true. These are the installation's and the calculator's statements. Runner holds them to the case and to the mapping's limits.
- That any real calculator answers in this shape. The tests sign answers in the shape the contract states.
- The `darwin/amd64` archive is built and read, and run by nothing. `jpack-google-relay` is started by no release check.
- The archive checks start no job: a released program needs Runtime and a boot line to start one. CI's tests start jobs from source, within the test's own process. Nothing here tests the exchange of the boot line with Desk.
