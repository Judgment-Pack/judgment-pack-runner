# v0.32.0

Runner v0.32.0 adds a second storage kind for service mode, on PostgreSQL 16 (#264). To
make that possible, everything a Runner keeps now goes through one store contract, and the
sqlite kind, the default, sits behind it with the same schema and the same bytes
(#254, #258, #262). A new public package, `sdk/dialect`, prepares input in process and reads
the proposed dialect format `4.0.0`, and `verify-preparation` reads it too (#260).

A Runner started as before, with the sqlite kind and no `store` member, keeps its store's
schema and its records' bytes. The Spec's maturity remains `draft`. This release claims no
Extended Runner support.

## Behaviour changes

On the sqlite kind (#254, #258, #262, #260):

- A brief's command is read from the request before the brief's transaction. A request
  whose body is refused and whose stored history does not decode now answers the body's
  refusal first.
- Writing or revising a trigger or job that is not held is `absent`. A trigger configured
  through another job is refused as `absent`, as it was refused before.
- A repeated creation whose earlier job record does not decode answers no job beside its
  error, where it used to answer the part that decoded.
- A retry whose attempt changed between the check and the write answers `409
  attempt_mismatch`. A retry whose run was interrupted between the read and the write
  answers `409 run_not_retryable`.
- A unique key met at the write names its key, and a release's key answers `409
  release_already_used` with the message of the key that was met.
- A finish of a run that is not `running` is refused by the store instead of overwriting
  it. Nothing in the Runner does that today.
- A `4.0.0` dialect on a release, job, preview, validate or workflow path was refused `400
  invalid_source_input` and is now refused `422 dialect_format_not_admitted`.

On a kind that leases claims (#264): the restart interrupts only runs that no live claim
holds; on the sqlite kind it interrupts every run held running, as before.

## What an operator must do

- **Nothing, to keep running as before.** Stop Desk and Runner and back up the Jobs
  workspace before the upgrade, as
  [State and backups](../../README.md#state-and-backups) describes.
- **To use the second storage kind,** make the database and the four roles as
  [the postgresql store kind](../postgresql-store.md) describes (the owner, the migration
  login, the request login, the worker login). The Runner makes no role.
- **Run `jpack-runner store migrate --connection <absolute path>` as a release step,
  before starting a newer Runner on the store.** A start never migrates. A start refuses a
  store that is not migrated or whose applied migrations are not exactly this Runner's
  set, an older set and a newer one alike.
- **Write the `store` member** in the service configuration:
  `{"kind":"postgresql","connection":"<absolute path>"}`. The connection file is held to
  the configuration's file rules and is refused inside the state directory. The state
  directory is still required.
- **Know what a start refuses** on this kind: a run-time login that is a superuser,
  bypasses row security, can create roles or databases, or is a member of the owner; a
  request login that is the worker login or a member of it; grants made to other logins
  than the ones configured; a store identity that is another Runner's; and a
  configuration that asks for manual admission.
- **Run one Runner per store.**
- **Take backups with a role that bypasses row security,** kept for backups and never
  named to the Runner. Restoring a store from a backup is not tested.
- **Expect a Runner that loses a claim to stop.** When a lease renewal fails, conflicts or
  is late, the Runner stops the attempt's Runtime, writes nothing more for that run and
  stops its dispatcher; `GET /v1/health` then reports it unhealthy and it needs a restart.
  A run left running by a Runner that stopped is interrupted by the tick once its lease
  has run out, about a minute later.

## Store contract (#254, #258, #262; closes #263 with #264)

- **One contract.** `docs/design/store-interface.md` section 9 lists every piece of state a
  Runner writes: 20 kinds in its database and 8 kinds of files under its state directory.
  The contract covers the journal's reads and filters, refusals, profile rows, briefs,
  scope identifiers, schema raises, triggers, occurrences, jobs made and revised, the job
  and run listings, manual mode and relocation. The Service holds no database handle.
- **Transaction functions are safe to run twice.** Each starts from copies of its inputs,
  assigns its results only at its end, and reads only the store, its arguments and the
  clock. The in-memory kind has a mode that runs every function twice, and the unit-test
  script requires that mode to run.
- **A scope held to a transaction.** A transaction or a read can be held to a scope
  identifier; the store as opened reaches every scope. `POST /v1/jobs` and the job upgrade
  are held to the scope they name.
- **A claim.** Each claim of a run carries a token of 16 random bytes and a lease by the
  store's clock (60 s, renewed every 15 s). A write with another claim's token, or after
  the lease ran out, writes nothing.
- **A build-failing check:** a test fails when a database value or a statement appears
  outside the sqlite kind's files.
- **Outside the contract,** with the reason recorded in `docs/design/store-interface.md`:
  the workflow store (no route reaches it) and the source worker's own database.
- **Design.** `docs/design/store-postgresql.md` holds decisions D1 to D15;
  `docs/adr/0001-second-storage-kind.md` is the decision record, status proposed.

## Reading dialect format 4.0.0 (#260; closes #251)

- **`sdk/dialect`** is a public package with no network dependency. It reads a `4.0.0`
  dialect that has no source and gives `Prepare` and `PrepareBatch`, and a parameter
  digest, plain and keyed (`hmac-sha256`), which excludes `runAt`.
- **`verify-preparation`** reads `4.0.0` with or without sources.
- **Every other path** refuses it with `422 dialect_format_not_admitted`: releases, jobs,
  previews, validation and workflows do not admit the format until the Spec settles it for
  workflows and recordings.
- **Agreement with the Spec's staged vectors:** 167 of 167 rows and both end-to-end vectors
  agree through the verifier, and 162 through the package; the other five are format
  `3.0.0` rows, declined by design.

## The postgresql storage kind (#264; closes #263)

- **Selection.** A `store` member `{"kind":"postgresql","connection":"<absolute path>"}` in
  the service configuration. Without it, the store is the sqlite kind.
- **Migration.** `jpack-runner store migrate` applies numbered, digested migrations as the
  migration login, never at start. A second run applies nothing. It refuses a database
  that holds a table outside the store's schema and the system's, a file recorded under
  another digest, a recorded migration it does not ship, and a replaced request or worker
  login. `jpack-runner store` takes `migrate` and nothing else.
- **Scopes held apart by forced row-level security.** Row security is enabled and forced on
  every table, the owner included. A request login's transaction sets the scope identifier
  for that transaction alone; a transaction that sets none reaches no scoped row. A
  worker login does the work for every scope. Rules that span scopes (one job per release,
  identity of a pack or dialect never reused with other bytes, trigger and queue limits,
  one trigger per cloud binding) are held by keys and counters no policy narrows. A
  request held to one scope can learn that some scope holds a release or an identity,
  never which. Journal sequences are shared across scopes, so a page shows gaps.
- **Claims fenced by token and lease.** A claim's token, attempt and lease are checked in
  the statement of each claimant write, with the database's clock. The Runner renews the
  lease every 15 seconds; a failed or late renewal stops the Runtime at once, and the tick
  interrupts runs whose lease ran out.
- **Writes** are serialized on a journal head row and retried on serialization failure and
  deadlock within a bound.
- **Routes served on this kind:** `GET /v1/health`, `GET /v1/status`, `POST /v1/previews`,
  `POST /v1/jobs`, `GET /v1/jobs`, `GET /v1/jobs/{job}`, `POST /v1/jobs/{job}/upgrade`,
  `GET /v1/jobs/{job}/upgrade-receipt`, `GET /v1/runs`, `GET /v1/jobs/{job}/runs`,
  `POST /v1/jobs/{job}/runs`, `GET /v1/runs/{run}`.
- **Every other route answers `501 store_route_unsupported`** before it reads anything,
  among them the journal routes, the run chain, triggers and occurrences, a run's retry,
  and the input preparation routes.
- **What stays on the host's disk:** the attempt directories, the pinned Runtime and a
  preview's scratch directory. A missing attempt directory is taken to be unknown, never to
  hold no audit record.
- **New dependency:** `github.com/jackc/pgx/v5` v5.12.0 (`THIRD_PARTY_NOTICES`).
- **CI:** a `PostgreSQL store` job on a `postgres:16` service container runs the kind's
  conformance (and its twice mode) and the design's section-10 tests, and fails if any of
  them skips.
- Operator guide: `docs/postgresql-store.md`.

## What this release does not establish

- **Routes not served on the second kind.** Every route outside the list above answers
  `501 store_route_unsupported`.
- **Removal of one scope's rows is not built** (design D10). `jpack-runner store` has no
  command for it.
- **Several Runners on one store is not a supported arrangement yet (#245).**
- **No process group on stop (#265).** Starting each Runtime in a process group of its own
  is not built on any stop path.
- **Tests not built (#267):** section-10 tests h, D5, D9's own, D11, D13, D14 and the
  routes-use-their-logins test.
- **Also not built in the kind:** attempt volume rows (D11), the pinned Runtime directory
  (D12), the migration's row marker, and the cloud binding's `taken` answer.
- **Restoring a store from a backup is not tested.**
- **Dialect format `4.0.0`:** the reading agrees with the Spec's staged vectors and is by
  the same maintainer as the reference reader, so it is not an independent implementation
  and makes no conformance claim. Not built: moving the format `3.0.0` preparer into the
  package, sources in process, admitting `4.0.0` jobs, the `extended` profile.
- **A scope is a label and a filter on the sqlite kind** as in v0.31.0. TODO(maintainer):
  confirm whether to repeat the v0.31.0 limitations that stand (no TLS, retry against a
  stub, no conformance claim for Core `0.5.0`); the pull requests do not restate them.
- TODO(maintainer): the review records list a `PostgreSQL store` job that is not a
  required check on `main` (a repository setting, recorded in #268); decide whether the
