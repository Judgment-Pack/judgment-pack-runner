## `verify-run` names the instant freshness is judged against (#55)

- **A program that reads `verify-run`'s report** sees one new member, `unsignedFreshness`, on every run with a verified acquisition that was not skipped, copy mappings included; it is absent for an export without lineage. It names `preparation.verifiedAt`, the instant each acquisition's freshness and each computed calculator's table freshness were judged against, and the sources judged. Without the record's binding (below), no signature covers that instant: freshness is consistent with the instant the export supplies; nothing establishes that instant was the admission instant. The line on standard error says the same.
- **The instant is committed in the signed record, from Runtime 0.31.0 on (#55).** On every operational evaluation of a mapping-v2 run, Runner passes the Runtime a binding, `{"kind":"judgment-pack-runner/preparation/1","digest":"sha256:…"}`, whose digest is the SHA-256 of the run's `preparation` in the canonical form a frozen release is digested by; the record carries it, under the chain and the record signature (runtime ADR-0050). Never on a rehearsal. A Runtime before 0.31.0 is given none and evaluates as before. A completed mapping-v2 run says which, as `binding`: `bound`, `unsupported-runtime`, or `unversioned-runtime` for a build that names no release (`0.0.0-dev`), which is given none. A Runtime that refuses the binding fails the run with the reason `binding-refused`: a defect of Runner, never retried without it.
  - **A program that reads `verify-run`'s report** sees one new member first, `binding`, on every export with lineage: `matches`, `mismatch`, `absent` or `foreign-kind`. `verify-run` recomputes the digest from the export alone and compares the record's member as recorded. A binding of another scheme is refused (`binding-foreign-kind`) before any digest is compared, and one that is not the export's preparation's is refused (`binding-mismatch`): a moved `verifiedAt` is refused, where it was reported; under `--require-signed` the rewrite of the binding needs the key. A record without a binding is reported `absent`, keeps `unsignedFreshness` and its sentence, and is refused only with the new `--require-bound` (`unbound`), which also refuses an export without lineage.
  - **What it establishes:** for a binding that matches, in a record whose signature verifies, the preparation, its instant included, is the one Runner handed the Runtime for the record that was signed, and the line says the instant is committed in the signed record. A program knows it when `binding.status` is `matches` and `signature.status` is `signed`; `unsignedFreshness` keeps its name. Not against the operator, who holds the key and can sign a recomputed preparation's record again: only a witnessed chain (`--require-witnessed`) shows that. Nor the admission instant: the binding carries no time.
  - **Tested with Runtime v0.31.0:** CI pins Runtime `v0.31.0` (`8869f0d`), moved from `v0.30.0`, and keeps `v0.27.1` as the Runtime without the binding.
