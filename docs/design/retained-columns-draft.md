# Retained columns: selected RC2 integration

This is an experimental dependency slice for Agent #171 and Draft RFC0029.
The pure conversion foundation retains its original `dd2cc944` corpus and focused
evidence. Generated consumer integration follows the reviewed Draft inventory
amendment merged in Spec `be16a0f427c881cc7428ad0ceedb7ed4a8511d6c` (tree
`00a7e3eeb8a7b3eea5ce84f0f7c97f345d193646`, schema
`d402d26ed35f9cd8a3ab5f8a0a8288d222742d1742c00ebee47d81dc4766d725`, corpus
`395381002de6f50793d4d484c48ec2fc8eb4ed34d55afcf91e1b47b14e79c10e`).
Those historical fixtures were not an adoption claim. The earlier unselected slice advertised no public `retained-column/1`
capability. The scoped experimental Base adapter is described below; Extended
Runner remains unsupported. Old foundation corpus coverage is not a claim
that it executed the amended producer probes.

A dialect case fact can add a closed `conversion` leaf; case evidence can add a
closed `availability` leaf. The leaves enter the dialect and read digests.
An absent profile on ordinary mappings retains historical encoding and limits; `extended` refuses
with `profile-unsupported`. Integer 2/3 and named 2.0.0/3.0.0 formats retain
their original family and identity.

```json
{"target":"/eligible","source":"/retained","conversion":{"contractVersion":"1","column":"Eligible","kind":"boolean","trueValue":"YES","falseValue":"NO"}}
```

The existing `POST /v1/inputs/next` preparation path derives converted values
from the retained frame. Case source context establishes asserted classification;
caller `origin` supplies no generated authority. Generated case frames refuse.
Text, decimal, number, boolean, research-value and availability use the same
pure interpreter. Research-value needs a generated original typed declaration.
Issues and noncanonical candidates emit no successful preparation or evaluation.
Missing/blank/null/unavailable values retain distinct transformation states.

Generated conversion requires explicit `profile:"base"`, an operation bound by
profile ID and complete profile digest, and a trusted host InputProfile annotation
`retainedColumnProducer:{contractVersion:"1",grammar:"desk-reviewed-input/1"}`.
The trusted profile must be generated/MCP, source `desk-inputs`, endpoint
`desk-local:reviewed-inputs`, only tool `read_reviewed_input`, and exact
`jpack-desk/reviewed-input` adapter version `2` with the independently trusted
digest. Adapter version 1 is unsupported for this grammar. These are host pins,
not request-provided trust objects. A wrong pin or source is refused before any
acquisition is planned. Unwrap and calculation bindings cannot select this path.
Converted leaves select exactly `/retained` in the closed carrier.

The carrier is exactly `contractVersion`, `originalSnapshotJson`,
`originalSnapshotSha256`, and `retained`. Runner verifies the existing real
receipt signature, profile, request commitment, source/adapter/endpoint and
freshness checks. The signature domain remains the canonical result. It then
checks the full snapshot/frame relation from the reviewed Draft: complete
ordered original declaration inventory (including unselected fields), only
JSON whitespace removed from raw declaration tokens outside strings; full
unfiltered `record.values`; all original typed field statuses/raw presence and
tokens; and the exact original run/recipe-version relation. Filtered top-level
snapshot values cannot substitute. Other original snapshot members remain
retained, including historical escaped lone surrogates; decoded duplicate names
are rejected throughout. No original byte or Unicode normalization is applied.

Both frame revisions equal the domain-separated SHA256 over the exact validated
original run ID and positive safe literal recipe version, always 71 ASCII bytes.
The current root qualification revision cannot replace the original record/run
revision. Revision identity is not authority. Production adapter v2 must actually
load the original document history at the record's recipe version and compare
its complete inventory before issuing this wrapper. This consumer and its
handwritten signed fixtures do not implement or prove that producer precondition.

The new optional SourceValue form is exactly `{retainedResponseJson:<exact signed
envelope text>}`, mutually exclusive with `response` and `snapshot`. Historical
ordinary forms remain unchanged. Generated input may initially use `response`;
on successful preparation Runner retains only exact envelope text, avoiding a
redundant serialized object while preserving received bytes through JSON transport.
The text is strict UTF-8/duplicate-checked and transiently parsed; the original
signature/request/profile/freshness checks run on it. Both/neither response forms,
null/empty or misspelled members and unsolicited ordinary-path use refuse.
Canonically equivalent outer whitespace/spelling is not authenticated by the
receipt; raw envelope/frame hashes remain separate local evidence identities.
The complete original snapshot string is authenticated as string content by the
existing canonical result domain. The Draft-only structural projections and
handwritten vectors are in `internal/runner/testdata/retained-column-producer-draft/`;
they confer no authority and do not change public schemas.

The next experimental Draft amendment retains source inputs by reference. A
present transformation input is exactly
`{"state":"present","ref":{"frameSha256":"sha256:…","location":"values"}}`
(or `research-value`); missing is exactly `{"state":"missing"}`. The parent column
selects the original value. `values` resolves compact string/null JSON;
`research-value` resolves the exact original `valueJson` string. References are
recomputed from the exact raw frame UTF-8 bytes in the selected source/read/receipt
occurrence. A matching digest does not authorize another occurrence. Result,
omission reason, candidate tokens and conditional original research identity stay
inline and are independently recomputed. Preview input JSON is a separate diagnostic.
Old inline transformation inputs are refused by this new experimental wire form.

Asserted case custody uses the existing `case` object on initial input or sole
`retainedCaseJson` exact object text on the explicit Draft Base case-conversion
route. Enclosing mapping/source/import members remain unchanged. The two case
slots are mutually exclusive; null/empty/wrong-case members, decoded duplicate
keys and unsolicited ordinary-route text refuse. Initial raw cases with column leaves also require explicit `base`; this prevents
emitting custody that cannot replay. Successful preparation retains
only exact text, preserving whitespace, raw numeric tokens and original provenance
through HTTP, checkpoints, imports, exports and offline replay. Automatic seeds
retain it before their first durable save. Workflow getters transiently materialize
it while preserving existing case digest/comparison domains. No global custom
marshaler changes ordinary absent-member bytes. Complete accounting includes string
escaping, source siblings and both imported and bound mapping documents.

and corpus SHA-256
`f5de0701bb989f6a5b606e15d3409e4d5df43fe9227cfdd672e2410ac249b571`

The Go reader checks its seventeen new derivation/reference rows; the separate Spec

Each converted target gains optional `columnTransformation`, including conditional
original research identity, recomputed from the retained raw frame. Portable
claims retain their existing five members. `VerifyPreparation` and `VerifyInputs`
replay the same signed acquisition and complete relation; they reject substituted
transformations. Original two-member copies and absent optional profile, response

string and every JSON escape. Runner rechecks that aggregate after retaining
the exact text. Without an explicit selection, the unchanged Base ceiling is 2097152 bytes, original snapshot
ceiling 524288, preparation ceiling 8388608 and existing complete export/record
limits remain enforced at their actual existing entries. Ordinary body, canonical numeric and import limits remain unchanged. The new

## Scoped Base consumer and transport selection

The selected installed contract is published Spec `v0.3.0-rc.2`, commit
`bcac15b7537ce21879201b5e5dfe795496225121`, version `0.3.0-rc.2`, schema
`sha256:0cb49f238c78391cb163a65474cc9af962df2bb1024a55c5310c2b784b2f0557`, corpus
`sha256:17b16ff7a9b74fe4cc81eb6f6129a6aabdd9834621d9e756aa2d4c1a3f245863`.
Its maturity remains draft. The earlier sections describe preserved historical
foundation evidence; the selected corpus is separately byte-pinned. These constants
cannot be replaced by an HTTP request or host configuration. Extended Runner remains
unsupported. Runtime document validation alone does not establish complete Runner support.
Selected releases additionally admit Runtime's existing Core `0.3.0` Base evaluator,
while preserving selected and ordinary `0.2.0-draft`. Ordinary and manual admission
are unchanged. Evaluation and replay require the evaluator version from that same
retained release pack; mismatched or unknown reports refuse.

Published synthetic preparation fixtures exercise preparation consistency with a
fixed test-only installation and the companion's receipt conditions. They do not
establish Gateway chain authenticity or complete signed export validity. Public
verification retains those full checks. Actual signed lifecycle tests separately
exercise both supported selected Core versions against an explicitly identified Runtime.
The synthetic source-input probes with a v2 root `snapshot` are outside Runner's
existing v2 grammar, which requires named sources; they do not extend that grammar.

Authenticated `/v1/retained-column/1/inputs/next`, `/inputs/preview`, `/previews`,
`/jobs/{job}/runs`, and `/runs/{run}/verification` adapt the corresponding existing
operations. They require one `JPack-Conversion-Contract` header: strict canonical
unpadded base64url of exactly `{contract,spec,profile,roles}`. `contract` is
`retained-column/1`; `spec` has exactly `version`, `revision`, `schemaSha256` and
`corpusSha256`; profile is `base`. Roles are a nonempty unique subsequence of
`document-validation`, `preview`, `preparation`, `preparation-verification`,
`producer-carrier`, in that order. Unknown tuples/profiles/roles or a missing
operation role refuse as `capability-unsupported`; malformed/duplicate/extra
members or noncanonical role order refuse as `input-malformed`. Authentication,
origin guard and selector validation precede body reads. Unsupported scoped routes
explicitly refuse. Ordinary routes reject selected input and retain their defaults.

Preparation operations require document-validation, preview and preparation.
Selected generated reads additionally require producer-carrier, separately from
existing grammar, profile, signature, request, freshness, inventory and revision
checks. The approved host profile carries optional `conversionContracts` entries
with the closed RFC capability shape and exact producer grammar. These are trusted
registration/configuration metadata bound to the existing profile digest. A source
input cannot install or replace them. Missing producer support refuses before
planning or dispatch. Runtime is independently queried at its actual read-only
`dialect contract` entry before selected release preview and evaluation; only an
exact document-validation tuple with sufficient document/frame capacity passes.

The exact selector is optional `conversionContract` on SourceInput and Preparation.
Existing complete preparation bindings include it. Release sample, run input,
planned source and durable source-operation request retain it. Release/run mismatch
and resumed operation rebind refuse. The selector and frame digest add no signing
or source authority. Case and response custody remain sole exact text alternatives.

Every artifact limit applies independently; complete serialization, escaping and
sidecars count. Existing nesting, numeric, target, field, original snapshot and
string bounds remain. Exact custody strings use member-specific bounds; ordinary
canonical claims keep their canonical domain and default cap. Signature sidecar,
chain and checkpoint bounds remain independently enforced. The optional execution
admission/governance route remains explicitly unsupported for selected source inputs.

Offline `verify-run` and `verify-preparation` accept `--conversion-contract` with
the same bounded header encoding, checked before larger files are opened. The API
`VerifyInputs` accepts an explicit optional selector and PreparationFixture carries
it separately. They never infer selection from retained bodies. Offline readers
revalidate source/preparation/release identities and complete size limits against
their own installed manifest. Every selected export version, including version 2,
independently bounds its parsed audit token and its complete release/run owner
encodings; the export base/wire allowance does not replace those limits. Versions
3–5 additionally bound the exact original record bytes, chain and signature
sidecars. Disposition replay retains the complete verified input through Runtime
admission, including the exact Runtime's lower document/frame maxima, before any
evaluation. Existing invocations retain ordinary admission.


Lower positive owner reports are valid. Runner takes the minimum of its Base
ceiling and the approved profile's reported maximum, then measures the complete
profiles, signed response, carrier and decoded original snapshot separately.
Online planning and offline preparation use the same trusted profile, including
its existing identity, signature and original-inventory checks. Planned and
durable source requests retain all six effective producer ceilings; a changed
installation cannot rebind an in-flight request. These downward caller ceilings
grant no authority and never enlarge Base. A durable `retainedColumn` discriminator is derived only from the trusted
profile and mapping read; producer requests without these ceilings are refused
before dispatch. Ordinary selected mixed-source acquisitions retain their prior
behavior. Resumed intent must match both the discriminator and ceilings, so a
producer request cannot be downgraded into an ordinary request. Runtime document reports are likewise
minimized and checked against the pack, published and bound mappings, and every
retained frame before validation/evaluation effects. The independent binding
document remains capped at 64 KiB.

Runner receives the signed Gateway response; it cannot observe producer grant
creation or adapter stdout. The retained grant/stdout ceilings are obligations
of those actual owners, not evidence supplied by offline verification or a
Gateway fixture. Producer-owner negotiation and proof remain separate required
integration evidence.
